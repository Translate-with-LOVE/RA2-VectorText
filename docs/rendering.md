# VectorText 渲染说明

## 支持范围与加载

补丁由 Syringe 加载，目标是 `gamemd.exe 1.001`，全部 hook 地址属于游戏本体。
不需要 Phobos、Ares 或 cnc-ddraw；FreeType 静态链接进 DLL。
当前目标程序的日志指纹为大小 `0x00497FE0`、时间戳 `0x3BDF544E`、CRC32 `0x1B499086`。
其他版本需要重新核实函数字节与调用约定。

字体文件由配置指定，位图回退使用游戏正在使用的 game.fnt 数据。
只覆盖进入原生 BitFont 文字管线的内容；预制图片或 SHP 中的文字不会变成矢量字形。
补丁输出到游戏 RGB565 表面，最终画面仍受游戏分辨率、呈现缩放和 16 位颜色精度影响。

## 渲染流程

游戏先锁定文字表面，并决定每行字符范围、换行、Y、阴影遍数、显现进度和调用颜色。
补丁在行入口准备自然 advance、英文 kerning 和四分之一像素 X 位置，随后在原有 Blit
调用中按这些位置绘制。返回给游戏的 X 仍使用原字宽字节加 `BitFont+0x2C` tracking，
维持原循环、换行和显现流程；绘制 X 与返回步进分别计算。

字体表不会因单行布局被改写。行状态按线程隔离；调用者、font、表面、裁剪框、字符
和原始 X/Y 必须与计划一致，防止其他行或另一遍绘制使用当前计划。Unlock 清除状态。
预检先完成整行布局，失败时不会只画出一段新排版前缀。

### 自然字距与宽度约束

- 英文使用 FreeType kerning；中文逗号、句号、成对括号与引号使用紧凑标点槽，调整侧留白。
- 中英文单词交界按实际墨迹补至四分之一中文 em 的间隔；已有空格或标点分隔时不重复添加。
- 居中和右对齐按新行宽恢复原锚点；部分显现不改变整行的对齐位置。
- DrawText 使用行框宽度；DrawString 使用实际裁剪框；PrintUnicode 传递视口矩形和原对齐锚点。
- 过窄时先收紧已有空白，普通墨迹间隔至少保留半像素，中英文交界至少一像素。
- 仍放不下时整行等比缩小，最低 90%，字距与标点槽使用相同比例；需要更大幅缩小时整行回退。

字形不做横向拉伸或压扁，也不按字符分别缩小填满旧字格。
不支持复杂文字 shaping；UTF-16 代理对回退。超过 2048 个 UTF-16 单元、未锁定表面、
游戏字体缺字或带对齐的 Tab 行也回退。普通 Tab 保留游戏原停位规则。

### 位图图标与矢量文字混排

矢量字体缺字而游戏字体有有效位图时，同一行保留原图标、尺寸和步进，其余文字继续自然排版。
当前回退格式是 16 行、每行 3 字节、每字形 49 字节的 MSB-first 1bpp 点阵。
位图图标不做缩放；整行必须缩小时回退。

电力闪电 U+26A1 与矿车镐 U+26CF 使用这条通用路径，ASCII 数字、正负号和斜杠
仍使用 Arial 13px 的自然 advance。绘制和测量共用布局，无需识别计数器字符串或外部 DLL。
回归覆盖 `⚡+1710`、`⚡-1000`、`⛏2/2`、`⛏10/12`，与原位图图标加独立自然排版数字逐像素比较。

## 统一基线与画质

默认中文为 `NotoSansSC-VF.ttf` 16px、可变字重 450，英文为 `arial.ttf` 13px 常规体。
固定字体的字重由文件决定，`FontWeight` 不改变 Arial 的字重。

`BaselineRow=13` 是相对于游戏传入 Y 的共同基线位置；字形顶点由 FreeType 纵向轴承决定。
中英文、数字、符号不会根据各自轮廓边界上下补偿。缓存记录 `inkY` 和实际位图行数，
允许笔画超出旧 16 行字格，写入时按真实表面和文本框裁剪。
直接绘制的逐字回退也保留共同基线和完整纵向轴承；swap 模式需要旧固定字格，使用独立缓存键。

`Supersample=1` 在目标像素尺寸栅格化，`Hinting=0` 使用 LIGHT，主要沿纵向对齐笔画并保留水平比例。
`Hinting=1` 使用 NORMAL，`Hinting=2` 关闭 hinting；不支持的值回到 LIGHT。
无抗锯齿时使用 MONO。切换 hinting 清空缓存，自然步进使用 `linearHoriAdvance`，
因此 hinting 和采样方式不改变设计字距。

默认 `Gamma=1.0`、`LinearBlend=1`，保留灰度覆盖率，在较高精度的线性空间混合后输出 RGB565。
自然单行字形保留侧轴承和边缘；启用 FitToAdvance 的逐字回退按旧显式字宽裁掉边缘溢出。
字体设计、小字号采样、RGB565 量化及最终缩放共同决定观感，预览应以 100% 查看。

## 动态框与背景宽度

`DynamicTextWidth=1` 开启，`LineWidthPadding=4` 为测量额外余量，范围 1～32。
设为 `DynamicTextWidth=0` 恢复原动态框度量。

加载目标框使用最长显式行的自然宽度向上取整再加余量，以旧测量宽度作为最小值，
避免缩窄后触发原游戏提前自动换行。各行保留自然字距，无须被迫铺满相同宽度。
战役消息背景按每行自己的自然文字宽度留余量，保留原矩形留白。
其他测量和自动换行探测保持原值；不修改文本、不虚增字符、不伪造 maxChars。

测量和绘制共用自然字形、kerning、紧凑标点与混排间隔。
测量不锁定表面、不画像素、不替换当前绘制计划。显式行或加余量后超过 maxW、
缺字、Tab 或不支持的输入保留原结果，避免测量高度与游戏选出的行数不一致。

### 原生调用帧约定

测量入口 `0x433CF0` 保存文本对应的自然宽度到线程局部记录。
游戏在 `0x433E45` 将累加宽度写入原入口栈 +4，覆盖原文本指针；出口不能再读取它作为字符串。
成功出口 `0x433E7F` 按入口 ESP（当前 ESP +20h）和调用者匹配记录，消费一次后应用宽度。
出口栈 +8=font、+20=返回地址、+28=pWidth、+2C=pHeight、+30=maxW。
寄存器、栈、高度和原 `ret 10h` 保持原约定。

适配只应用于加载目标调用者 `0x553199/0x5531EF`，以及 GetTextWidth 返回地址 `0x433EE6`
且上层调用者（出口栈 +34）为 `0x623A81` 的消息背景。未完成或不匹配记录不应用到其他栈帧。

## Hook 与内存约定

| 入口 | 地址 / 覆盖字节数 | 用途 |
| --- | --- | --- |
| Drawing::GetTextDimensions | 0x4A59E0 / 10 | 观测测量调用 |
| Drawing::PrintUnicode | 0x4A61C0 / 10 | 观测文字调用 |
| BitFont::GetTextDimension | 0x433CF0 / 6 | 保存动态宽度测量 |
| BitFont 测量成功出口 | 0x433E7F / 6 | 更新适配范围内的宽度 |
| BitText::Print | 0x434B90 / 5 | 观测单行调用 |
| BitText::DrawText | 0x434CD0 / 5 | 观测富文本调用 |
| BitFont::Blit | 0x434120 / 5 | 按计划绘制，或逐字回退 |
| BitFont::DrawString | 0x434500 / 7 | 准备普通行 |
| DrawText 显式换行 | 0x434D91 / 6 | 准备游戏选择的行 |
| DrawText 自动换行 | 0x434FA3 / 6 | 准备游戏选择的行 |
| DrawText 最后一行 | 0x43518E / 6 | 准备游戏选择的行 |
| BitFont::Unlock | 0x434990 / 7 | 清除单行状态 |
| PrintUnicode 视口 | 0x4A5FD6 / 6 | 传递实际框宽和原对齐锚点 |

DrawString 入口 ECX=font，栈 +4=text、+8=X、+C=Y、+10=maxChars。
三个 DrawText 行入口 EBP=行起点，栈 +4C=行结束、+44=font，EAX=原对齐偏移，
栈 +50=框起点 X、+54=Y、+58=框宽、+60=对齐标志（1 居中，2 右对齐）。
对应 Blit 返回地址为 `0x434EA6/0x4350E1/0x4352BA`，普通行为 `0x43464D`。
视口入口 EDI=RectangleStruct（X/Y/W/H）、ESI=原 X、EBP=Y、EBX=font，
栈 +10=text、+44=旧宽度、+50=Drawing 标志（0x100 居中，0x200 右对齐）。

| BitFont 偏移 | 含义 |
| --- | --- |
| +04 | InternalData 指针 |
| +0C | 已锁定像素缓冲 |
| +10 | pitch，单位为像素 |
| +20 | Tab 使用的原点 X |
| +24 | 当前 16 位颜色 |
| +28 | Tab 宽度 |
| +2C | 原字符串循环的字符间附加步进 |
| +30..+3C | LTRB 裁剪框 |

像素地址为 `(uint16_t*)base + y * pitch + x`。
InternalData 的 +18 是 65536 项码位映射，+1C 是位图基址，+14 是字形字节数。
字形索引为 `SymbolTable[ch]-1`，首字节为原字宽，其后为点阵。
阴影和重描来自调用者多次绘制，颜色和偏移继续由游戏决定。

成功的 Blit hook 返回 `ret 10h` 跳板，将新笔位放在 EAX，保持保存的 ESP 不变。
Syringe 的 `popad` 会跳过保存的 ESP 槽，不能通过改写 REGISTERS.esp 来模拟函数返回。
跳板字节为 `8B 14 24 83 C4 14 52 C3`，负责真实的返回地址和四参数弹栈。
其他入口与拒绝路径返回 0，由 Syringe 重放原指令。

## 构建、验证与排查

执行 `build.bat` 生成游戏目录 DLL 和 INI；重启游戏加载。

| 检查 | 验证范围 |
| --- | --- |
| `line_test.bat` | 混排、kerning、对齐、框宽、显现、Tab、整行回退、线程隔离、无相位漂移 |
| 同上：原生测量回归 | 从本地游戏复制 0x433CF0..0x433ED0 机器码并重定位；CPU 执行原算法与返回；调用已安装 DLL hook，检查参数槽覆盖、宽度、高度、异常输入及记录消费 |
| 同上：无外部扩展回归 | 明确确认 Phobos/Ares 未加载，再验证四组计数器的完整像素、旧步进和 ESP |
| `baseline_test.bat` | 与独立 FreeType 位图逐像素比较，覆盖中英文、数字、符号、1x/2x/4x、三种 hinting、四种 X 相位、缩放与顶边裁剪 |
| `render_quality_test.bat` | 生产配置在黑底与纹理背景的预览；覆盖率、缓存、自然步进、颜色通道与原字体数据不变 |
| `takeover_test.bat` | 逐字回退的颜色、AA、裁剪、未锁定拒绝、缺字拒绝和吞吐 |
| `hooktest_draw.bat --mode draw` | 返回跳板、ESP/EAX 和拒绝路径；支持 aa/swap/observe 模式检查 |
| `python tools\verify_dll.py` | x86 DLL、13 条钩子记录、导出、重定位以及无 Phobos/Ares 普通或延迟导入 |

生产预览输出 `build/render-qa/raster-after.bmp` 和 `raster-scene.bmp`。
单独比较参数时修改该 QA 目录的 INI，并在该目录运行
`render_quality.exe comparison.bmp --check --line`；加 `--scene` 使用纹理背景。
各次运行独立初始化配置和缓存，不修改游戏目录 INI。

游戏目录的 `VectorText.log` 中，`LINE ready` 表示计划成功，`LINE fallback` 表示整行回退，
`LINE native icon` 表示位图图标混排，`DYNAMIC width` 表示动态框测量适配命中。
检查 `EXE` 指纹与 `WARN` 可定位游戏版本问题；字体初始化信息可核实实际路径、字号和基线。
首次几次命中日志用于诊断，不代表每次调用都会重复输出。

工具 `analyze_log.py` 汇总实际调用日志，`find_callers.py` 扫描原生调用点，
`screenshot_diff.py` 比较同分辨率的同一静态场景。离线通过仍需结合游戏画面验收。

## 回退开关

- `LineRender=0`：改用逐字绘制；不启用自然单行布局。
- `DynamicTextWidth=0`：保留原动态框度量。
- `Mode=observe`：只观测文字管线，让游戏绘制原文字。
- 修改配置后重启游戏生效。构建会将项目 INI 复制到游戏目录。
