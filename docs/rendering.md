# VectorText 渲染说明

## 支持范围与加载

补丁由 Syringe 加载，目标是 `gamemd.exe 1.001`，全部 hook 地址属于游戏本体。
不需要 Phobos、Ares 或 cnc-ddraw；FreeType 静态链接进 DLL。
当前目标程序的日志指纹为大小 `0x00497FE0`、时间戳 `0x3BDF544E`、CRC32 `0x1B499086`。
其他版本需要重新核实函数字节与调用约定。

字体文件由配置指定，位图回退使用游戏正在使用的 game.fnt 数据。
只覆盖进入原生 BitFont 文字管线的内容；预制图片或 SHP 中的文字不会变成矢量字形。
游戏场景仍使用原 RGB565 表面；有 cnc-ddraw 时，文字可直接在 BGRA8 呈现阶段合成，
消除文字边缘的 5/6/5 量化。字号、字体设计和最终呈现缩放仍会影响观感。

## 模块边界

Syringe hook 在 `Hooks.cpp` 和 `hooks/` 中读取原生参数，调用 `Takeover.h` 的接口。
`takeover/LineLayout.cpp` 准备和消费整行计划，`Measurement.cpp` 使用同一套自然字距原语进行只读测量，
`Takeover.cpp` 负责字体初始化和逐字回退；拒绝统计与返回跳板放在 `Diagnostics.cpp`。
每个线程的行计划由布局模块持有，待消费的背景、tooltip 和宽度测量由 hook 测量模块持有。
私有头文件只连接这些实现单元，不提供另一套渲染算法。

`GlyphSource.cpp` 管理缓存和访问锁；`glyph/Fonts.cpp` 管理 FreeType 库、字体与字号，
`Settings.cpp` 处理栅格设置、旧码位映射、字体选择和 kerning。
缓存未命中时，`Raster.cpp` 加载字形并串联 `Outline.cpp` 的轮廓调整与 `Coverage.cpp` 的位图生成。
逻辑覆盖率和可选 2× 字形使用同一次轮廓调整结果，各自保留对应采样网格的 hinting。
缓存及 FreeType face 仍由 `GlyphSource` 统一持有；栅格化各步骤在同一把锁内完成。

字形经缓存后交给 `PixelWriter`。没有 32 位接管时写入 RGB565；接管时调用
`presentation/State.cpp` 登记的 writer，向 `PixelPlane` 稀疏文字层记录覆盖率。
`Surfaces.cpp` 跟踪 DirectDraw 表面和加载界面的 BSurface，负责复制、填充、清除与销毁时的文字层同步。
加载界面的内存表面和游戏内显示表面保持各自的登记与复制路径。

| 呈现实现 | 边界 |
| --- | --- |
| `Presentation32.cpp` | 检测 cnc-ddraw、验证游戏入口、安装 hook 和公开接口。 |
| `presentation/State.*` | 唯一的呈现状态、原函数槽、锁、文字 writer 和帧统计。 |
| `presentation/Surfaces.cpp` | 原生表面及文字层的生命周期和复制/填充同步。 |
| `presentation/Gdi.cpp`、`OpenGL.cpp` | 各后端的 BGRA8 转换与上传，保留原目标矩形和状态。 |
| `presentation/D3d9.cpp` | D3D9 纹理接管、上传、GPU 合成和设备状态恢复。 |
| `presentation/Atlas.*` | 高分辨率稀疏图集、边界采样和实际视口倍率计算。 |
| `presentation/TestAccess.cpp` | 测试适配器；只编入显示测试，不进入 DLL。 |

`Config.cpp` 负责 INI 解析与 `Cfg` 访问器，`Logger.cpp` 负责记录调用及输出摘要。
配置仍通过日志的现有初始化锁延迟加载；通用配置查询保留原读取时机，布尔解析及默认值不因拆分改变。
CMake 分别构建字形、布局/配置、文字层静态库，DLL 和显示测试使用同一份呈现源文件列表。
FreeType、MinHook 都使用固定提交的 submodule；自有代码的格式规则在 `.clang-format` 中。

## 渲染流程

游戏先锁定文字表面，并决定每行字符范围、换行、Y、阴影遍数、显现进度和调用颜色。
补丁在行入口准备自然 advance、英文 kerning 和四分之一像素 X 位置，随后在原有 Blit
调用中按这些位置绘制。返回给游戏的 X 仍使用原字宽字节加 `BitFont+0x2C` tracking，
维持原循环、换行和显现流程；绘制 X 与返回步进分别计算。

字体表不会因单行布局被改写。行状态按线程隔离；调用者、font、表面、裁剪框、字符
和原始 X/Y 必须与计划一致，防止其他行或另一遍绘制使用当前计划。Unlock 清除状态。
预检先完成整行布局，失败时不会只画出一段新排版前缀。

### 自然字距与宽度约束

- 英文使用 FreeType kerning；中文逗号、句号、成对括号与引号使用紧凑标点槽，调整侧留白。
- 中英文单词交界按实际墨迹补至四分之一中文 em 的间隔；已有空格或标点分隔时不重复添加。
- 居中和右对齐按新行宽恢复原锚点；部分显现不改变整行的对齐位置。
- DrawText 使用行框宽度；DrawString 使用实际裁剪框；PrintUnicode 传递视口矩形和原对齐锚点。
- 过窄时先收紧已有空白，普通墨迹间隔至少保留半像素，中英文交界至少一像素。
- 仍放不下时整行等比缩小，最低 90%，字距与标点槽使用相同比例；需要更大幅缩小时整行回退。

字形不做横向拉伸或压扁，也不按字符分别缩小填满旧字格。
不支持复杂文字 shaping；UTF-16 代理对回退。超过 2048 个 UTF-16 单元、未锁定表面、
游戏字体缺字或带对齐的 Tab 行也回退。普通 Tab 保留游戏原停位规则。

### 旧码位兼容与布尔配置

`LegacyCodepage1252=true`（默认）将输入 `U+0080～U+009F` 中 Windows-1252 定义的
27 个位置转为对应 Unicode 字形，例如 `U+0092 → U+2019`、`U+0099 → U+2122`。
5 个未定义位置保持原值；ASCII、汉字和已经正确编码的 Unicode 不受影响。
映射只用于矢量字形、字体选择、kerning、紧凑标点和背景测量。输入字符串、CSF 文件、
game.fnt 字符索引、引擎原步进和显现循环保留原值；含旧码位的行与正确 Unicode 使用相同自然布局。
`LegacyCodepage1252=false` 严格按原始 Unicode 解释，适用于已改正字体码位的模组。
矢量缺字时继续使用原位图回退。这是补丁文字管线的兼容开关，不处理预制视频字幕图片。

所有布尔项支持不区分大小写的 `true/false`、`yes/no`、`on/off` 和原有 `1/0`。
缺失或无效值使用该项默认值；字号、像素边距、Hinting 等整数/枚举项不按布尔解析。
配置在游戏启动时生效，修改后需重启。

`Mode` 只保留三个值（不区分大小写）：

| 值 | 行为 |
| --- | --- |
| `off` | 使用游戏原生文字，关闭矢量接管 |
| `observe` | 观测原生文字调用，不替换绘制 |
| `draw` | 启用矢量绘制，按其他开关选择单行布局及呈现路径 |

缺失或未知值（包括以前的其他模式名）按 `observe` 处理。
`Enabled` 控制日志和 32 位呈现启动；要关闭全部矢量绘制，使用 `Mode=off`。
仓库根目录的 `VectorText.ini` 为完整示例，已显式列出 `AntiAlias=true`。
无实际作用的旧配置 `FitMode`、`ClassAlign`、`FallbackOnError`、`MetricsExcept` 已删除；
旧 INI 中保留这些项会被忽略。错误及缺字仍按既有规则回退到原生绘制。
`AntiAlias=false` 使用单色覆盖率；`HiDPI` 和 `LegacyCodepage1252` 是独立布尔开关，
不需要旧的缩放数值选项，也不改变 Hinting 的枚举语义。

### 位图图标与矢量文字混排

矢量字体缺字而游戏字体有有效位图时，同一行保留原图标、尺寸和步进，其余文字继续自然排版。
当前回退格式是 16 行、每行 3 字节、每字形 49 字节的 MSB-first 1bpp 点阵。
位图图标不做缩放；整行必须缩小时回退。

电力闪电 U+26A1 与矿车镐 U+26CF 使用这条通用路径，ASCII 数字、正负号和斜杠
仍使用 Arial 13px 的自然 advance。绘制和测量共用布局，无需识别计数器字符串或外部 DLL。
回归覆盖 `⚡+1710`、`⚡-1000`、`⛏2/2`、`⛏10/12`，与原位图图标加独立自然排版数字逐像素比较。

## 统一基线与画质

默认中文为 `NotoSansSC-VF.ttf` 16px、可变字重 450，英文为 `arial.ttf` 13px 常规体。
固定字体的字重由文件决定，`FontWeight` 不改变 Arial 的字重。

`BaselineRow=13` 是相对于游戏传入 Y 的共同基线位置；字形顶点由 FreeType 纵向轴承决定。
中英文、数字、符号不会根据各自轮廓边界上下补偿。缓存记录 `inkY` 和实际位图行数，
允许笔画超出旧 16 行字格，写入时按真实表面和文本框裁剪。
直接绘制的逐字回退也保留共同基线和完整纵向轴承。

`Supersample=1` 在目标像素尺寸栅格化，默认 `Hinting=0` 使用 LIGHT，主要沿纵向对齐笔画并保留水平比例。
`Hinting=1` 使用 NORMAL 完整网格对齐；`Hinting=2` 关闭 hinting；不支持的值回到 LIGHT。
无抗锯齿时使用 MONO。切换 hinting 清空缓存，自然步进使用 `linearHoriAdvance`，
因此 hinting 和采样方式不改变设计字距。

单行渲染也遵循 `Subpixel`：默认 `true` 使用四分之一像素字形相位，保留灰度边缘和更精细的位置；不是 RGB 子像素彩色抗锯齿。
自然布局、kerning、混排间距和背景测量仍保留四分之一像素，返回游戏的旧步进也保持原值；
不逐字取整 advance，因而不会累计整行长度误差。`Subpixel=false` 可将可见字形原点取最近整数像素，
每字最多偏移半像素，相邻可见字距可能有一像素的取整差异。原生 1bpp 图标保持原有整数定位。
当前 `Hinting=0` 保留轻量纵向对齐，避免完整网格对齐造成笔画边缘过硬。
`render_quality_test.bat` 同时生成 RGB565 与 BGRA8 的黑底、纹理背景预览，
BGRA8 预览复用实际单行 hook 路径、兼容像素及 `PixelPlane` 合成，但不模拟最终显示缩放。

### cnc-ddraw 的 32 位呈现

`Present32=true`、`Mode=draw` 时，补丁检查 ddraw.dll 的特征导出，接管原生
DirectDraw 创建及表面接口，不依赖 Phobos 或 Ares。没有 cnc-ddraw、配置关闭、
表面格式不受支持或呈现接入失败时，继续使用 RGB565 路径。
适配针对本机 cnc-ddraw 1.3.5，测试包含 Direct3D9、OpenGL 和 GDI。
本机当前 D3D9、OpenGL、GDI 的实际显示像素、复制、清除和翻页检查均通过，
D3D9 的 2×、小数倍率、动态缩放及全屏兼容检查也通过。其他驱动和 cnc-ddraw 版本仍需验证。

游戏文字 hook 生成的字形被保留在与像素缓冲区地址关联的稀疏文字层中，
同时在 RGB565 中保留兼容像素和其原始背景。最终合成直接使用高精度覆盖率与原始背景，
不把兼容像素再次混合，也不把兼容像素的量化结果作为最终文字颜色。
普通复制、透明色复制、拉伸、镜像和区域清除同步处理文字层；
翻页交换像素地址，呈现时从公开表面描述刷新对应关系。递归释放附属表面也会清理记录。
Lock/Unlock 和呈现前检查兼容像素是否仍然存在；CPU/SHP 恢复原黑底或 HUD 背景后，
对应文字层失效。黑色阴影和极弱覆盖率也保留可识别的兼容标记，最终画面不显示标记。
同一表面的重复绘制替换上一轮覆盖率，避免反复叠加导致字重逐渐变粗。
另外在本机游戏核实并接管 `DSurface::FillRectEx (0x4BB620)`：
FillRect 和 Fill 也经过这个入口，CPU 写入相同黑底时仍会清掉对应文字层，保留裁剪框。
游戏软件 Blit 的栅格复制入口 `0x437350` 也同步文字层：普通复制替换目标区域，
零色键复制保留透明背景并转移源文字。同步遵循游戏的成对裁剪规则，区分 DSurface
与直接持有内存的 XSurface；原生复制失败时恢复文字层。内部 Lock/Unlock 不重复
对已同步的复制执行像素差异失效检查，避免背景变化时误删新转移的文字。
加载界面在 `0x552D94..0x552DCD` 构造原生 `BSurface`，不是 DirectDraw 表面。
BitText::Print/DrawText 入口按确切 vtable `0x7E2070` 登记其内存文字层；
每次绘字前验证兼容像素并开始新一轮覆盖率，随后通过同一个 `0x437350` 复制入口转移文字。
在已核实的标量删除析构入口 `0x411650` 释放记录，先清理文字层再让游戏释放内存，
防止后续复用相同对象或像素地址时留下旧字。目标尺寸、pitch 或分配地址变化时重建记录。
加载图可能在首个 GPU 上传前绘字，因此该内存目标先保留高精度采样和 RGB565 兼容像素；
呈现器就绪后按实际输出比例合成，不改变游戏内的字体参数。析构入口不匹配时此目标继续使用 RGB565。
独立文字层不再只依赖这些入口：直接 CPU 恢复背景也能使旧覆盖率失效。
离线真实 cnc-ddraw 测试覆盖了数字居中位置变化、位数减少，以及 1000 次直接内存
黑底恢复后移动红字；实际遭遇战的黑幕、残影和卡死仍需用新 DLL 复测。
运行时核实 EXE 时间戳、DSurface vtable 入口及填充/复制指令前缀；不匹配时回退 RGB565。

- Direct3D9：将 cnc-ddraw 的 R5G6B5 上传纹理提升为 A8R8G8B8。原渲染器写入
  16 位暂存矩形，Unlock 将背景扩展到 32 位并合成文字，GPU 纹理不再经过 RGB565。
- OpenGL：分配 RGBA8 纹理，上传时将背景和文字合成为 BGRA8，恢复原像素解包设置。
- GDI：将原 16 位位图转换为 32 位 DIB，保留源行方向、目标矩形及缩放。

### 原版过场字幕擦除

原版字幕通过 `BitText::DrawText`（调用点 `0x6C9E78`）绘制，先按原位图字宽、
16px 行高测量，再把 X/Y/W/H 保存到字幕对象 `+0x14`，供下一帧填黑擦除。
矢量字体的实际宽度、负向笔画和独立高清采样可能超出这个矩形；换句后留下的
绿色逗号、黄色碎片来自旧字幕像素，不是字幕字符串的多余码位。

`hooks/Text.cpp` 仅在这个字幕调用进入时开启线程内绘字范围捕获；`PixelWriter`
记录实际字符位置及裁剪后的低/高分辨率笔画，包含换行、自然布局及逐字回退。
`0x6C9E7D` 返回点把原矩形与捕获范围取并集，随后让原生代码保存擦除框。
这不修改字幕文字、时间、颜色、位置、换行或原字体表，也不依赖 `DynamicTextWidth`。
捕获按调用栈匹配并一次消费；未绘字和非 draw 模式维持原框。

`line` 检查调用实际 DLL 字符和字幕 hook，复现原框遗漏的像素，再验证三种颜色
完整擦除；`cpu_loading_text` 另检查只在 HiDPI 采样中出现的负向笔画和下缘。
`verify_dll.py` 核对返回点、矩形寄存器和栈局部变量的原生机器码。

### 自动 HiDPI 文字输出

`HiDPI=true`（默认）读取 D3D9 最终画面四边形和源纹理坐标，判断实际 X/Y
缩放比例。窗口、无边框/独占全屏、整数缩放、视口偏移及每游戏配置覆盖，都按
cnc-ddraw 最终生效的结果处理；不只依据 `windowed` 或 `fullscreen` 的单一标志。
X/Y 均放大时启用高分辨率文字，包括 1.25×、1.333×、1.5×、1.75× 等小数倍，
以及原版开场、过场的非等比宽屏拉伸（800×600→3840×2160 为 4.8×3.6）。
任一轴不放大或其他后端继续原合成。读取的是实际画面四边形，不单独将
Windows 的 DPI 百分比叠加到字号上，保持与画面、鼠标及背景框的坐标一致。
窗口调整后重新判断，首帧及资源分配失败时保持 1×；显卡不支持所需纹理或线性
混合时回退，不反复尝试失败的分配。`HiDPI=false` 使用原 1× 合成，也不分配 2× 字形缓存。

高分辨率字形由独立 FreeType face 按实际较大倍率向上取整，在 2～8× 源尺寸直接栅格化。
原版 800×600→3840×2160 的 4.8×3.6 输出使用 5×：中文 16→80px，英文 13→65px。
保留逻辑 advance、kerning、四分之一像素 X 相位、基线、换行和背景测量。
每个逻辑像素保留 N×N 个独立覆盖率采样；2× 继续内嵌四个采样，较高密度
使用不可变共享栅格，缓存字幕每帧复制时不重复分配。复制、镜像和清除均同步处理。
两轴输出倍率恰好等于栅格密度时点采样，否则 GPU 线性过滤并按两轴投影。
呈现线程只发布密度，游戏线程在下一次绘制更新字体缓存；整数密度变化时才重新生成。
已经缓存的文字保留原栅格直到游戏重新绘制；超过 8× 的输出受 8× 源限制。
日志 `glyph retained raster=N` 确认文字接管及实际栅格，`atlas raster=N` 确认 GPU 图集密度。

高清文字层启用时世界纹理只含原背景，由 cnc-ddraw 原滤镜（包括 Bicubic）绘制。
同一帧的文字在最终 D3D9 画面上另行合成，使用目标网格采样；不再经过世界层
的 Bicubic 放大。调用后恢复 D3D9 全部状态。上传纹理分别保存文字快照，避免
双缓冲中混入下一帧的覆盖率。线性抗锯齿使用预乘颜色、sRGB 读写及混合能力检查。
每次上传只提交当前文字块，旧图集单元不参与后续绘制；原生 CPU 写入的失效检测继续生效。

日志 `Present32: output text scale=2x2 viewport=3840x2160 logical=1920x1080`
说明 1080p 游戏画面实际以 4K 呈现，呈现器已启用目标分辨率文字路径，
不能单凭这一条证明某个绘字目标已接管。加载界面还需检查
`Present32: CPU text surface registered ... hi-raster=1`；它确认内存表面已保留高分辨率采样，
最终复制与显示效果需结合加载画面验收。
该路径把有文字的 32×16 逻辑像素块的 64×32 高分辨率采样打包成紧凑图集，
每格四周复制相邻文字的 2 个高分辨率采样作为滤波边界，单元为 68×36。
文字碰到块边缘时补上滤波覆盖到的相邻单元；表面之外填透明，消除小数倍率下的块间接缝和串色。
图集按实际文字块数量增长。GPU 用一次三角形批次只叠加这些块，不再更新或
混合整张 4096² 文字纹理。无文字时不上传图集、不做额外绘制；原生 1×
全屏不会分配这类图集。每张世界上传纹理保留自己的图集和块列表。

整屏自复制只快照活跃文字块，避免滚动时分配约 100 MB 的密集数据。
像素混合使用保持原舍入结果的 32 位整数计算，缓存当前颜色的覆盖率表，
并在绘制/上传时复用块查找。文字字形、字号、基线和灰度采样保持一致。
清空的块保留有界的可复用存储，减少逐帧重复分配；复制快照不包含备用块。
`Detailed=false`（默认配置）只记录统计，不收集逐条变化的文字内容。
需要定位实际游戏瓶颈时可临时设置 `PresentProfile=true`；日志每 300 帧记录
绘字、原生复制同步、上传和叠加耗时。默认关闭，记录的是 CPU 耗时，不是
GPU 完成时间或整局 FPS。

世界仍使用 cnc-ddraw 的滤镜、纹理坐标和呈现流程，不做额外横向拉伸。
字形颜色仍来自游戏传入的 16 位颜色；提升的是覆盖率合成和边缘颜色精度。
GDI 路径在第一次有效呈现后启用文字层，未就绪时先使用原路径。
原生游戏截图若直接读取 RGB565 表面，包含兼容文字；桌面截图包含最终高精度文字。

公开 DirectDraw 操作、游戏的 DSurface 填充和 XSurface 软件复制入口同步文字层。
绕过所有复制入口移动文字时，仅兼容像素随原生内存移动，无法恢复高精度覆盖率；
此类文字会以原生 RGB565 精度显示。写入值恰好等于兼容标记时仍无法区分覆盖和保留。
已核实的原生 BSurface 内存文字目标也同步文字层；其他未识别内存目标继续走原路径。
该适配器按游戏进程生命周期使用，运行中不支持卸载 DLL。
Syringe 读取握手时不会修改自己的导入；MinHook 初始化和呈现 detour 安装均在 loader lock 外。

日志 `Present32: ... promoted to BGRA8` 或启用信息可用于诊断；
`cnc_present_test.bat` 的 `backend=1/2/3` 分别表示 GDI、D3D9、OpenGL。
`REFUSE bounds` 按首次及指数间隔记录实际失败的原始框、夹紧框、pitch、字符、位置和调用者。
`PROBE` 只记录对象首次使用，不能代表后续拒绝。`skip-dispatched(9)` 表示跳过跳板已派发，
不表示已经确认调用者返回，更不能据此排除补丁或呈现线程的问题。

默认 `Gamma=1.0`、`LinearBlend=true`，保留灰度覆盖率，在较高精度的线性空间混合。
原路径回写 RGB565，`Present32` 呈现路径直接输出 BGRA8。
自然单行字形保留侧轴承和边缘；启用 FitToAdvance 的逐字回退按旧显式字宽裁掉边缘溢出。
字体设计、小字号采样、RGB565 量化及最终缩放共同决定观感，预览应以 100% 查看。

## 动态框与背景尺寸

`DynamicTextWidth=true` 开启，`LineWidthPadding=4` 为测量额外余量，范围 1～32。
设为 `DynamicTextWidth=false` 恢复原动态框度量。

加载目标框使用最长显式行的自然宽度向上取整再加余量，以旧测量宽度作为最小值，
避免缩窄后触发原游戏提前自动换行。各行保留自然字距，无须被迫铺满相同宽度。
战役消息背景按每行实际墨迹边界留左右各 2px（`LineWidthPadding` 至少 4px，分配到两侧）。高度按整行墨迹留上 1px、下 2px，
默认 16px 中文墨迹配原生 19px 行间步进时，各行背景恰好相接，不重叠。
背景的 Y 随实际墨迹调整，文字 Y、显现与颜色流程、下一行步进均保留原值。
原生 tooltip 按最长显式行的自然宽度加余量，以旧测量宽度为最小值。
游戏随后添加左右共 8px 的原生内边距，并以新宽度限制弹框右边界。
背景高度使用第一行到最后一行的实际墨迹范围，再加原生上下各 2px 留白。
绘制入口将整个文字块平移到该留白内，保留原行距、字号和原高度对应的行数预算，
避免缩短背景后 DrawText 提前结束而漏掉最后一行。墨迹包含字顶、下伸笔画及原位图图标。
可能自动换行的长提示、刻意设置首尾空行的提示保留原高度，不通过缩小字形补偿边距。
侧栏状态标签（含“就绪”）在原生矩形出口按真实栅格笔画的上下边界调整背景，
四周各留至少 2px，背景左右边界也按实际笔画计算，覆盖英文 Ready 和中文“就绪”。
仅调整背景矩形，文字的对齐锚点、位置和字号保持不变。2x 呈现时这些边距也按 2x 显示。
墨迹测量使用相同的自然布局、像素相位和对齐锚点，不复用当前绘制计划；不支持的输入保留原矩形。
其他测量和自动换行探测保持原值；不修改文本、不虚增字符、不伪造 maxChars。

测量和绘制共用自然字形、kerning、紧凑标点与混排间隔。
测量不锁定表面、不画像素、不替换当前绘制计划。显式行或加余量后超过 maxW、
缺字、Tab 或不支持的输入保留原结果，避免测量高度与游戏选出的行数不一致。

### 原生调用帧约定

测量入口 `0x433CF0` 保存文本对应的自然宽度到线程局部记录。
游戏在 `0x433E45` 将累加宽度写入原入口栈 +4，覆盖原文本指针；出口不能再读取它作为字符串。
成功出口 `0x433E7F` 按入口 ESP（当前 ESP +20h）和调用者匹配记录，消费一次后应用宽度。
出口栈 +8=font、+20=返回地址、+28=pWidth、+2C=pHeight、+30=maxW。
寄存器、栈和原 `ret 10h` 保持原约定；只有匹配的 tooltip 显式行会调整高度。

适配只应用于加载目标调用者 `0x553199/0x5531EF`、原生 tooltip 调用者 `0x478F0B`，以及 GetTextWidth 返回地址 `0x433EE6`
且上层调用者（出口栈 +34）为 `0x623A81` 的消息背景。未完成或不匹配记录不应用到其他栈帧。
tooltip 的墨迹顶部偏移和原行数预算，仅由 `BitText::DrawText` 返回地址 `0x479041`、字体和文本匹配后消费一次。
侧栏状态矩形调用者为 `0x6A9DD1`，经原生 GetTextWidth 的 `0x4A59F6` 嵌套路径捕获实际字体，
在 `0x4A5A40` 更新背景 X/Y/宽度和高度寄存器 EDI，原指令继续写入高度并恢复寄存器、执行 `ret 14h`。
任务消息在 `0x623A97` 调整背景：嵌套测量成功后，按字体与当前文本 EDI 匹配并消费墨迹记录。
更新矩形的 X/Y/宽度和待写入高度 EBP，不改 ESI 指向的文字行框。
该位置在 Phobos 的 `0x623A9F` 半透明背景 hook 之前，覆盖的 8 字节恰好在其入口结束。
Phobos 启用新消息背景时从 EBP 写入高度并调用半透明填充；关闭或未安装时仍由原生填充使用同一高度。
不替换 Phobos 的透明度，也不再与它共用 hook 地址。

| 入口 | 地址 / 覆盖字节数 | 用途 |

| Drawing::GetTextDimensions | 0x4A59E0 / 10 | 观测并保存侧栏状态背景锚点 |
| Drawing 测量矩形出口 | 0x4A5A40 / 5 | 侧栏状态背景按实际墨迹留上下边距 |
| 任务消息背景 | 0x623A97 / 8 | 在 Phobos 与原生填充前调整单行背景高度 |
| Drawing::PrintUnicode | 0x4A61C0 / 10 | 观测文字调用 |
| BitFont::GetTextDimension | 0x433CF0 / 6 | 保存动态宽度测量 |
| BitFont 测量成功出口 | 0x433E7F / 6 | 更新动态宽度及 tooltip 墨迹高度 |
| BitText::Print | 0x434B90 / 5 | 观测单行调用 |
| BitText::DrawText | 0x434CD0 / 5 | 观测富文本并对齐 tooltip 上下留白 |
| BitFont::Blit | 0x434120 / 5 | 按计划绘制，或逐字回退 |
| BitFont::DrawString | 0x434500 / 7 | 准备普通行 |
| DrawText 显式换行 | 0x434D91 / 6 | 准备游戏选择的行 |
| DrawText 自动换行 | 0x434FA3 / 6 | 准备游戏选择的行 |

| BitFont::Unlock | 0x434990 / 7 | 清除单行状态 |
| PrintUnicode 视口 | 0x4A5FD6 / 6 | 传递实际框宽和原对齐锚点 |

DrawString 入口 ECX=font，栈 +4=text、+8=X、+C=Y、+10=maxChars。
三个 DrawText 行入口 EBP=行起点，栈 +4C=行结束、+44=font，EAX=原对齐偏移，
栈 +50=框起点 X、+54=Y、+58=框宽、+60=对齐标志（1 居中，2 右对齐）。
对应 Blit 返回地址为 `0x434EA6/0x4350E1/0x4352BA`，普通行为 `0x43464D`。
视口入口 EDI=RectangleStruct（X/Y/W/H）、ESI=原 X、EBP=Y、EBX=font，
栈 +10=text、+44=旧宽度、+50=Drawing 标志（0x100 居中，0x200 右对齐）。

| BitFont 偏移 | 含义 |
| --- | --- |
| +04 | InternalData 指针 |
| +0C | 已锁定像素缓冲 |
| +10 | pitch，单位为像素 |
| +20 | Tab 使用的原点 X |
| +24 | 当前 16 位颜色 |
| +28 | Tab 宽度 |
| +2C | 原字符串循环的字符间附加步进 |
| +30..+3C | LTRB 裁剪框 |

像素地址为 `(uint16_t*)base + y * pitch + x`。
InternalData 的 +18 是 65536 项码位映射，+1C 是位图基址，+14 是字形字节数。
字形索引为 `SymbolTable[ch]-1`，首字节为原字宽，其后为点阵。
阴影和重描来自调用者多次绘制，颜色和偏移继续由游戏决定。

成功的 Blit hook 返回 `ret 10h` 跳板，将新笔位放在 EAX，保持保存的 ESP 不变。
Syringe 的 `popad` 会跳过保存的 ESP 槽，不能通过改写 REGISTERS.esp 来模拟函数返回。
跳板字节为 `8B 14 24 83 C4 14 52 C3`，负责真实的返回地址和四参数弹栈。
其他入口与拒绝路径返回 0，由 Syringe 重放原指令。

## 构建、验证与排查

最低运行系统为 Windows 7，构建目标为 x86，C/C++ 运行库、FreeType 和 MinHook 静态链接。
编译宏统一限定 `WINVER/_WIN32_WINNT=0x0601`、`NTDDI_VERSION=0x06010000`；
DLL 和测试程序的 PE OS / subsystem 版本均为 6.1。
构建入口默认选择 MSVC 14.44（VS 2022），可通过 `VT_VCVARS_VER` 选择 14.29 或 14.3x/14.4x。
VS 2026 可以作为工具安装宿主，必须安装兼容工具集，CMake 拒绝其默认的 14.50+；
参见[微软平台支持说明](https://learn.microsoft.com/en-us/cpp/overview/supported-platforms-visual-cpp)。
当前使用的动态 GDI、OpenGL 和 D3D9 呈现接口不要求 Win8+ 或 Windows DPI API，
HiDPI 使用实际画面倍率，仍按驱动能力检查及现有回退路径工作。
`verify_dll.py` 对普通与延迟导入使用已审核的 Win7 kernel32 API 白名单；
新增模块、API 或按序号导入必须审核并更新白名单，不能只依靠 PE 版本判断兼容性。
静态 CRT 的新 API 探测保留旧 API 回退；导入检查并不覆盖所有运行时分支。
本机离线和显示测试不能代替 Win7 实机上的 DLL 加载、游戏与驱动验收。

执行 `build.bat` 通过 CMake 构建并部署游戏目录 DLL；仅在配置不存在时复制 INI，保留已有运行配置。重启游戏加载。

首次获取仓库时运行 `git submodule update --init --recursive`，取得固定版本的 FreeType 和 MinHook。
入口脚本使用兼容 Win7 的 MSVC x86、CMake 3.21+ 和 Ninja；可通过 `VT_VCVARS`、`VT_CMAKE` 指定工具。

实际刷新后切换为对应倍率的高清合成。

`startup-5x.bmp` 使用独立 5× 字形覆盖“读取中”和左右版权文字；加 `--startup --hidpi --raster 5` 生成。
开场右侧两行版权文字在原生 `0x531459/0x5314B3` 测量返回前改用自然字宽，保留原来的右侧 10px 留白。
该测量不包含背景框 padding，字号变化后整行按实际宽度定位，避免按旧宽度定位后退回逐字缩放。
`line` 检查实际 DLL 测量入口/返回钩子、原生旧码位商标符号和完整版权行的无缩放布局。
手动生成可运行 `render_quality.exe loading-2x.bmp --check --line --bgra --loading --hidpi`。
该预览验证字形和文字合成，不模拟最终世界层滤镜；实际游戏以桌面截图检查。

游戏目录的 `VectorText.log` 中，`LINE ready` 表示计划成功，`LINE fallback` 表示整行回退，
`LINE native icon` 表示位图图标混排，`DYNAMIC width` 表示动态框测量适配命中。
检查 `EXE` 指纹与 `WARN` 可定位游戏版本问题；字体初始化信息可核实实际路径、字号和基线。
首次几次命中日志用于诊断，不代表每次调用都会重复输出。

工具 `analyze_log.py` 汇总实际调用日志，`find_callers.py` 扫描原生调用点，
`screenshot_diff.py` 比较同分辨率的同一静态场景。离线通过仍需结合游戏画面验收。

过场字幕默认启用 `SubtitleOutline=true`：黄/白等亮字固定使用 `max(1, N/2)` 个高清采样像素的黑边，
即约半个游戏像素。暗字使用白内缘和黑外缘，各宽 `max(1, N/4)` 个采样像素，约四分之一游戏像素。
5× 栅格下，白内缘由 2 个采样减至 1 个，黑外缘仍为 1 个，避免亮白边压过字形。
原字幕颜色保留，擦除矩形包含完整描边。
同一句字幕不会按影片背景逐像素切换边缘颜色，避免一行字出现黑白断裂或随背景运动闪烁。
缓存层分别保留总描边及白内缘覆盖率，原生复制和擦除也保留这些信息。
RGB565 回退为 1px 外缘，暗字固定白边、亮字固定黑边，不随影片像素变色。
`subtitles-2x.bmp` 的每组上行为原字幕、下行为描边字幕，分别使用暗、亮和交错背景。
手动生成：`render_quality.exe subtitles-2x.bmp --check --line --bgra --subtitles --hidpi`。
黄色字幕检查：`render_quality.exe yellow-subtitles-5x.bmp --check --line --bgra --yellow-subtitles --hidpi --raster 5`。
加 `--movie-background frame.bmp` 可用 800×600 的真实影片帧检查同一句字幕：上行为无描边，下行为细描边。
该离线预览仍需结合游戏里的最终输出验收。

影片连续帧不能用实时字幕层校验旧的 GPU 上传数据。D3D9 在 `LockRect` 时复制稀疏文字层，
`UnlockRect` 只对该快照验证原生像素并生成世界纹理和高清图集；不会修改游戏线程正在更新的文字层。
软件字幕复制的原生兼容标记在目标 DDS `Unlock` 之前修正，避免 cnc-ddraw 已唤醒渲染后仍改变上一帧像素。

字幕间的空白帧只清空图集绘制列表，保留每张上传纹理的图集及栅格倍率。
实际字形倍率变化时重建图集；分配失败后下次上传仍可重试，不因图集指针为空永久关闭高清路径。
`cnc_present_test.bat --stretch-only` 在实际 D3D9 输出上连续检查字幕出现、消失及 5×/2×/5× 字形切换，
读取轮换上传后的屏幕像素，要求每帧保持高清覆盖率，并检查空白间隔没有残留。

## 回退开关

- `LineRender=false`：改用逐字绘制；不启用自然单行布局。
- `MixedScriptCenter=true`（默认）：中英文自然单行混排时，按字体的大写字面与中文字面中心计算统一的英文基线偏移。英文、数字及同字体符号一起移动，不逐字符居中或单独校正商标；字体原有的上标、下伸笔画相对基线关系保留。纯英文和纯中文不偏移。偏移以四分之一游戏像素栅格化，HiDPI 使用同一轮廓变换，墨迹测量包含偏移后的范围。
- `Present32=false`：关闭 cnc-ddraw 的 BGRA8 合成，使用 RGB565。
- `HiDPI=false`：保留 BGRA8，关闭跟随实际倍率的高清文字层。
- `SubtitleOutline=false`：关闭过场字幕对比描边。
- `DynamicTextWidth=false`：保留原动态框度量。
- `Mode=observe`：只观测文字管线，让游戏绘制原文字。
- `Mode=off`：关闭矢量接管，使用原生文字。
- 修改配置后重启游戏生效。部署保留游戏目录已有 INI。
