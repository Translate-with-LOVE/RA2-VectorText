# 单行 X 覆盖渲染

`Mode=draw`、`Metrics=game`、`AdvanceScale=1.0`、`LineRender=1` 启用。
`LineRender=0` 使用此前的逐字渲染。字体仍使用当前英文 13px、中文 16px、基线 13。

游戏继续决定换行、每行字符范围、Y、阴影遍数、显现进度和每次调用的颜色。
补丁提前准备该行的自然 advance、英文 kerning 和四分之一像素字位；
Blit 钩子用这些字位绘制，返回游戏原来的 X 步进（字宽字节加 BitFont+0x2C）。
自然字形共享 `BaselineRow`，保留纵向轴承；超出旧 16 行字格的笔画只按文本框裁剪，
不会根据单个汉字的轮廓边界上下挪动或缩小。
原字体表和换行规则不改写，字形不横压或拉伸。
通用宽度测量保持原值；动态任务目标框和消息背景的宽度单独适配，见下文。

中文逗号、句号、成对括号和引号采用紧凑标点槽，保留轮廓比例并调整侧留白。
DrawText 的居中/右对齐按整行新宽度计算，显现前缀不会改变整行锚点；
DrawString 使用 BitFont 的实际裁剪框得到可用宽度；PrintUnicode 的最终 Print 调用
另传递视口 RectangleStruct 与原对齐锚点，使普通路径也能按自然宽度重做居中/右对齐。
中英文单词交界按实际墨迹补至四分之一中文 em 的间隔；已有空格或标点分隔时不重复加空白。
窄文本框先收紧已有字间空白，普通边界保留至少半像素墨迹间隔，中英文交界保留至少一像素。
仍放不下时，整行使用同一个比例小幅等比缩小（最低90%），字距、kerning和标点槽一起缩小；
需要更大幅度缩小时才整行回退。没有逐字独立缩小，没有横向压扁或强制填满文本框。
矢量字体缺少某个字形而 game.fnt 有有效字形时，保留该字形的原位图、尺寸和步进，
同一行的其他文字仍使用自然矢量排版。位图图标不做缩放；需要缩小带图标的整行时回退。
预检失败（游戏字体也缺字、未锁定、超过 2048 个 UTF-16 单元或带对齐的 Tab 行）也整行回退。
不支持复杂文字 shaping；代理对会回退。ASCII 英文采用 FreeType 的字体 kerning。

## 钩子依据

地址和覆盖长度以本地 gamemd.exe 1.001 的反汇编及文件原始字节为依据。

| 入口 | 地址 / 字节数 | 输入 |
|---|---|---|
| DrawString | 0x434500 / 7 | ECX=font，栈+4=text、+8=X、+C=Y、+10=maxChars |
| DrawText 显式换行 | 0x434D91 / 6 | EBP=行起点，栈+4C=结束地址，+44=font |
| DrawText 自动换行 | 0x434FA3 / 6 | 同上 |
| DrawText 最后一行 | 0x43518E / 6 | 同上 |
| Unlock | 0x434990 / 7 | ECX=font，清除本线程单行状态 |
| PrintUnicode 视口 | 0x4A5FD6 / 6 | EDI=矩形、ESI=原X、EBP=Y、EBX=font；栈+10=text |

三个 DrawText 行入口均位于最终 X 写入之前：EAX=原对齐偏移，
栈+50=框起点 X、+54=Y、+58=框宽、+60=对齐标志（1居中、2右对齐）。
对应 Blit 返回地址为 0x434EA6、0x4350E1、0x4352BA；
DrawString 对应 0x43464D。只在对应调用者、font、缓冲、裁剪框、字符和原始 X/Y
均匹配时使用预排位置，避免把另一行或另一遍绘制混入当前状态。
视口入口栈+44=原测量宽度、+50=Drawing 标志（0x100居中、0x200右对齐）。
以原始 X 与旧宽度恢复对齐锚点，随后只用新宽度重新放置，不修改测量函数。

## 动态框与背景宽度

`DynamicTextWidth=1` 默认开启；`LineWidthPadding=4` 是测量时额外预留的像素，范围 1～32。
设 `DynamicTextWidth=0` 可恢复原来的动态框度量。

加载任务目标的真实日志显示：两行共用旧的 190px 框，第一行自然宽约 203.5px，
被收紧 13.5px，第二行自然宽 187.5px，不需要收紧，造成上下两行字距不同。
现在框宽使用最长显式行的自然排版宽度向上取整再加余量，示例为 208px。
保持旧宽作为最小值，避免缩窄后让原游戏提前自动换行。文字仍按各自行长绘制。

战役消息背景每行分别按自然宽度计算，原游戏的矩形留白仍保留。
背景绘制不再根据 game.fnt 的旧字宽估算新字形的长度。
测量与绘制共用 `NaturalGlyph`，包括英文 kerning、紧凑标点槽和中英文交界空白；
测量不锁定表面、不画像素，也不替换当前单行绘制状态。
它没有增加字符、修改字符串、伪造 maxChars 或改变逐字显现数量。

新增 `0x433E7F / 6` 成功度量出口钩子，原输出已经写入；
覆盖指令为 `mov al,1 / pop ebx / add esp,1Ch`，随后原 `ret 10h` 正常执行。
此时栈 +8=font，+20=返回地址，+28=pWidth，+2C=pHeight，+30=maxW。
**栈 +24 已不是文本指针**：原函数在 `0x433E45` 将累加宽度写到原入口栈 +4，
复用了字符串参数位置。入口 `0x433CF0` 必须先按原始文本、font 和 maxW 计算自然宽度，
保存在线程局部记录中；出口按原入口 ESP（当前 ESP +20h）和调用者匹配后仅应用保存结果。
保存结果只消费一次；下一次测量会清除未完成记录，其他栈帧不会接收这份宽度。
只处理任务目标的调用者 `0x553199/0x5531EF`，以及 `GetTextWidth` 返回地址
`0x433EE6` 且上层调用者（栈+34）为 `0x623A81` 的消息背景矩形。
普通文本测量、消息换行探测、返回寄存器、栈和高度输出不修改。

显式行超过原 maxW、自然宽加余量超过 maxW、缺字、Tab 或不支持的字符串时保留原测量。
自动换行仍由原游戏处理，避免只改宽度而让测量高度与绘制行数不一致。
修改后的离线测试覆盖上述两个调用路径、混排、CRLF、未锁定测量、背景右侧余量、
当前单行状态不变、无关调用者保持原度量、异常输入回退，以及加载两行不再收紧。
本轮之前的 DLL/INI 保存在 `backups/dynamic-width-before-20261007`。

### 实际调用帧回归

首版动态宽度出口错误地把累加宽度当作文本指针读取，实际游戏日志出现 1119 次异常，
没有成功的 `DYNAMIC width`，任务目标框仍为 190px。原先仅模拟未被改写的参数，
未覆盖这一原函数行为。失败的 DLL、INI 和实际日志保存在
`backups/dynamic-width-frame-before-20261007`。

`tools/dimension_machine_check.h` 从本地 gamemd.exe 读取真实 `0x433CF0..0x433ED0`
机器码，复制到独立测试进程并重定位两处跳表操作数和四个跳表地址。
测试桩按 Syringe 的寄存器约定调用已安装 DLL 的入口和出口钩子，原测量算法和
`ret 10h` 由 CPU 实际执行；测试只在回调期间替换调用者身份，真实返回地址随即恢复。
上一版 DLL 在该测试中返回 190px，修正版返回 208px，原高度仍为 40px；
出口观测到原文本参数确实已被覆盖为 190。消息背景路径、无关换行探测和失败出口也覆盖。
另有回归测试明确改写参数位置，并检查一次消费、栈帧匹配和未完成记录清理。
这些测试验证实际原函数与补丁的配合，仍不代替完整游戏画面的验收。

## 电力与矿车计数器

Phobos 的 `CreditsClass_GraphicLogic_HarvesterCounter` 包含两个计数器，
通过 `0x4A60E0` 格式化后走 `0x4A5EB0`，最终进入相同的 DrawString/Blit 路径。
截图的闪电与镐图标分别与 game.fnt 的 U+26A1（27 个墨迹像素）和 U+26CF
（39 个墨迹像素）完全一致。它们不在当前 Arial 字体中，旧预检因此拒绝整行。
随后 `+1710` 回到逐字符字格适配，7/0 被分别缩进 5px 字格，1 保留自己的尺寸，
同时继续使用旧步进。这是计数器字高、字距异常的原因。

现在缺失的矢量图标在同一行中使用原位图，ASCII 数字和正负号、斜杠仍使用 Arial
13px 的自然 advance，不再因为一个图标而逐字缩小。绘制和动态测宽使用相同混合布局。
回归测试覆盖 `⚡+1710`、`⚡-1000`、`⛏2/2` 和 `⛏10/12`，
将输出逐像素比对为原图标加独立自然排版的数字，并检查返回的旧游戏步进。
运行时首次命中输出 `LINE native icon: U+26A1/26CF`，便于确认游戏走到修正路径。

上述 Phobos 调用链仅用于定位截图的问题，修复本身没有依赖 Phobos/Ares 的模块、
接口、地址或计数器字符串。钩子挂在 gamemd.exe 1.001 原生文字函数，缺字回退读取
当前游戏字体的位图，任意调用者都能使用这条路径；只需由 Syringe 加载 VectorText。
离线测试明确确认进程未加载 Phobos/Ares，再调用游戏目录 DLL 的 DrawString/Blit
钩子，检查四种图标计数器的完整像素、旧步进和栈，以及原生背景测宽路径。

## 验证

构建：`build.bat`。单行功能与新增 DLL 钩子验证：`line_test.bat`。
它使用真实 game.fnt 及合成 RGB565 表面，覆盖 kerning、混排、对齐、显现前缀、
Tab、整行回退、负 X 裁剪、线程隔离、重复绘制，以及 Syringe ESP/EAX/ret-10h 约定。
`tools/render_quality_test.cpp` 增加 `--check --line`，可生成新旧同字号对比图。
`tools/verify_dll.py` 验证导出、钩子记录和重定位。
离线验证不等于游戏内视觉验收；日志首次准备的行以 `LINE ready` 标记，
过窄行首次回退以 `LINE fallback` 标记。
